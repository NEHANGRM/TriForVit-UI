1. Project Objectives

Academic Mandate

Hierarchical Multi-Task Inference

Jointly resolve binary image-level authenticity (det_logit), high-resolution 512×512 pixel segmentation localization (mask_logits), and multi-label manipulation classification (type_logits: Copy-Move, Splicing, Inpainting) in a single unified forward pass.

Explicit Copy-Move Self-Correlation

Address foundation model blind spots by introducing an explicit Layer 4 self-correlation branch with Chebyshev distance masking (suppressing diagonal $\|p_i - p_j\|_\infty \le 1$ artifacts) and mutual match normalization to catch cloned textures.

Boundary-Sharpened Edge Supervision

Formulate a hybrid loss function combining morphological edge band supervision ($ ext{dilated} - ext{eroded}$ ground-truth contours) to sharply penalize fuzzy or bled tampering boundaries along manipulated regions.

Generalization & Zero-Leakage Integrity

Enforce strict source-disjoint train/val splitting via perceptual hashing (pHash) to eliminate near-duplicate contamination, combined with post-processing augmentations (JPEG QF 50-95, Gaussian blur, noise) for robust cross-dataset resilience.

2. Problem Statement & Literature Gap

Research Motivation

⚠️ The Threat: Seamless Multi-Domain Digital Forgery

With the rapid proliferation of modern digital image manipulation software and deep generative inpainting engines, visual tampering has become imperceptible to the human eye. Digital image manipulations primarily fall into three distinct mechanisms:

1. Copy-Move (Cloning) Duplicating patches from the same image. Because both patches share the same camera sensor noise and illumination, standard classifiers completely overlook them.
2. Splicing (Object Ingestion) Compositing objects from distinct foreign images, introducing boundary frequency discontinuities and sensor PRNU mismatch.
3. Inpainting (Synthesis / Removal) Synthesizing or erasing regions using patch-match or deep diffusion, leaving blurred high-frequency noise residuals.

Limitations of Existing Approaches:

  • ✕ Block/Keypoint Methods (Fridrich et al.): Heavily brittle under post-processing (JPEG compression, blur, rotation) and completely fail in smooth textureless zones.
  • ✕ Global CNN Classifiers: Overfit to dataset-specific camera sensors and compression artifacts; cannot output pixel-level spatial masks.
  • ✕ Standard Vision Transformers (ViTs): Process patches purely semantically, lacking inductive bias for forensic noise discontinuities and duplicate patch correlation.
  • ✕ Prior Hand-Crafted Multi-Streams: Attempting to run 3 raw parallel streams (spatial, FFT, noise) creates severe gradient divergence, massive memory bloat, and lacks high-resolution convolutional mask decoding.

3. Methodology & Updated Architecture Flow (FTT v2)

Core Technical Contribution
Architectural Evolution: Why FTT v2 is NOT a Three-Stream ViT

From Conceptual Three-Stream to Production FTT v2 Architecture

In initial project reviews, our team proposed an ad-hoc Three-Stream Tokenization ViT (parallel spatial, FFT magnitude, and SRM noise streams). However, empirical validation and recent advances in forensic literature (e.g. DINOv3-IML, arXiv 2604.16083) revealed that ad-hoc parallel streams suffer from high training instability, feature collision, and cannot achieve high-resolution (512×512) pixel segmentation.

To solve this, our project evolved into FTT v2 (Forensic Transformer v2) on branch dkb/arch-fix. FTT v2 replaces parallel hand-crafted streams with a unified self-supervised DINOv3 ViT-S/16 foundation backbone adapted via LoRA (Low-Rank Adaptation), an explicit Self-Correlation Copy-Move Branch, and a multi-scale convolutional Mask Decoder:

✕ Legacy Three-Stream Concept (Phase 1)

  • Three raw separate streams (Spatial, FFT, SRM Noise)
  • Cross-attention fusion before standard ViT encoder
  • Image-level binary and type classification only
  • No high-resolution (512×512) pixel localization decoder
  • Optimization conflicts between divergent raw streams
  • High GPU memory consumption & training instability

✓ Updated FTT v2 Architecture (Current Production)

  • DINOv3 ViT-S/16 Backbone with PEFT LoRA (=64$)
  • Layer 4 Self-Correlation Branch: Chebyshev-masked (Chebyshev distance d > 1) patch affinity matrix for copy-move cloning
  • Convolutional Mask Decoder: Conv3×3 + GroupNorm + Bilinear 16× upsampling -> 512×512 pixel mask
  • Hierarchical Multi-Task Heads: Binary DetectionHead + Multi-label TypeHead
  • Boundary-Aware Edge Loss: Morphological dilation/erosion contour supervision
  • 100% Passing Unit Test Suite & zero-leakage hash split verification

FTT v2 End-to-End Pipeline Walkthrough

The framework processes an input image through 5 tightly integrated stages to generate pixel masks, image detection, and multi-label type probabilities:

Stage 1 • Input

Standardized Image Normalization (B, 3, 512, 512)

Input images are resized to 512×512 resolution using Lanczos/Bilinear interpolation and normalized using ImageNet channel statistics. Rigorous training augmentations apply JPEG recompression (QF 50-95), Gaussian blur, noise, and scaling.

Stage 2 • Backbone

DINOv3 ViT-S/16 Backbone + LoRA Adaptation

Self-supervised Vision Transformer foundation model (patch size 16×16, embedding dimension 384, depth 12). Base weights remain frozen while trainable LoRA adapters (=64, lpha=128$) inject adaptation directly into Query, Key, and Value self-attention projections.

Stage 3 • Correlation

Self-Correlation Copy-Move Branch (Layer 4 Tap)

Intermediate Layer 4 hidden states tap into an explicit patch correlation module. Computes normalized cosine affinity across all 32 × 32 spatial patches. Applies Chebyshev distance masking to suppress trivial diagonal self-matches (Chebyshev distance <= 1), followed by mutual match normalization and top-8 descriptor extraction -> cm_feat (B, 32, 32, 32).

Stage 4 • Decoder

Multi-Scale Convolutional Mask Decoder (512 × 512)

Concatenates Layer 12 hidden states with copy-move correlation features: [F_last, cm_feat] (384 + 32 = 416 channels). Passes through Conv3×3 + GroupNorm (8 groups) + ReLU, followed by 16× Bilinear upsampling to generate pristine mask_logits (B, 1, 512, 512).

Stage 5 • Heads & Loss

Hierarchical Task Heads & Boundary-Aware Edge Loss

Detection Head: 2-layer MLP pooling CLS token, mean patch tokens, and detached mask/correlation statistics -> det_logit (B,). Type Head: Multi-label MLP classifying copy_move, splicing, inpainting -> type_logits (B, 3). Supervised via FTTv2Loss: L_seg + 15.0 × L_edge + L_det + L_type.

5. Project Progress & Implementation Milestones

Phase Audits

Phase 0 — Repository Audit & Setup Oct 2026

Conducted full system audit of dependencies (Python 3.11+, PyTorch 2.6+, Transformers, PEFT, OpenCV). Documented legacy model limitations and created a deterministic CPU dummy transformer harness (backbone.name: dummy) ensuring tests run offline without Hugging Face API keys.

Phase 1 — Model Skeleton & Architecture Validation Oct 2026

Implemented ForensicModel nn.Module, PEFT LoRA attention injection, convolutional MaskDecoder, DetectionHead, TypeHead, and Chebyshev-masked Copy-Move branch. Passed Gate 1 unit test suite with 100% pass rate (45 passed, 0 failed).

Phase 2 — Data Pipeline & Zero-Leakage Splitting Oct 2026

Standardized manifest schema (src/ftt_v2/data/manifest.py). Implemented source-disjoint train/val splitting with perceptual hash (pHash) clustering to guarantee zero train/val overlap. Built manifest generation tools for CASIA v2.0, Columbia, COVERAGE, and Defacto.

Phase 3 — Multi-Task Losses & Overfit Gate Verification Oct 2026

Engineered FTTv2Loss combining segmentation BCE, morphological boundary edge loss, image detection BCE, and type cross-entropy. Executed 32-sample synthetic overfit gate test: achieved >80% loss reduction and Pixel F1 > 0.80 on forged samples.

Phase 4 — Progressive Pilot Ablation Experiments Oct 2026

Configured progressive ablation benchmarks: Stage A (Decoder-only baseline), Stage B (LoRA r=64 + Decoder), Stage C (Multi-task LoRA + Detection + Type + Decoder), and Stage D (Full model with Copy-Move correlation branch).

Phase 5 — Full Production Training & Kaggle Benchmarking Oct - Nov 2026

Ported training pipeline to Kaggle GPU accelerators with Mixed Precision (AMP), gradient accumulation, and cosine learning rate scheduling with warmup. Monitored pixel IoU, boundary F1, and multi-label mAP.

Phase 6 — Cyber-Forensics Interactive Web UI & Deployment Nov 2026

Constructed the ForgeSight (TriForVit-UI) cyber-forensic portal featuring an interactive curtain split-wipe viewer, bounding box overlay, pre-computed benchmark dataset, and hybrid support for cloud static hosting and local live Python MPS/GPU acceleration.
